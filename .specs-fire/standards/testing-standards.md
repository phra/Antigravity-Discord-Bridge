# Testing Standards

## Overview

Testing standards for the Antigravity Discord Bridge extension. Uses Vitest as the test framework and runner.

## Testing Framework

**Framework**: Vitest
**Runner**: Vitest (^4.0.18)

## Test Types

| Type | Tool | Location | When to Use |
|------|------|----------|-------------|
| Unit | Vitest | `src/__tests__/` | Pure logic, utilities, noise filtering |
| Integration | Manual | N/A | CDP bridge interaction, Discord bot flows |

## Coverage Requirements

**Target**: 70%
**Enforcement**: Manual (run `vitest run --coverage`)

**Critical paths that MUST have coverage:**
- Noise filtering logic (`utils.ts`)
- Message deduplication
- Queue management (size limits, ordering)

## Test Naming

**Pattern**: `should [expected behavior] when [condition]`

**Examples**:
- `should filter MCP noise lines` — Tests noise detection utility
- `should deduplicate identical message IDs` — Tests dedup set behavior

## Test Structure

```typescript
import { describe, it, expect } from "vitest";

describe("functionName", () => {
    it("should [expected behavior] when [condition]", () => {
        // Arrange
        const input = "test data";

        // Act
        const result = functionUnderTest(input);

        // Assert
        expect(result).toBe(expectedValue);
    });
});
```

## Mock Strategy

**Approach**: Manual mocks for VS Code API and external dependencies

**Guidelines**:
- Mock `vscode` namespace for unit tests (it's not available outside extension host)
- Mock `discord.js` `Client` for testing message handling without a live bot
- Mock WebSocket for CDP bridge tests
- Prefer dependency injection over global mocks where possible

## Test Data

**Strategy**: Inline test data with descriptive variable names

**Guidelines**:
- Use realistic Discord message objects for integration-like tests
- Include edge cases: empty messages, oversized content (>2000 chars), special characters
- Test noise filtering with real-world examples from CDP output

## Running Tests

```bash
# Run all tests
npm test

# Run with coverage
npx vitest run --coverage

# Run specific test file
npx vitest run src/__tests__/utils.test.ts

# Run in watch mode
npm run test:watch
```
